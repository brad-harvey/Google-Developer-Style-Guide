# Word list

*Source: [https://developers.google.com/style/word-list](https://developers.google.com/style/word-list)*

# Word list

An alphabetical glossary of specific terms with usage guidance (use / don't use / preferred alternative), condensed to short entries. This is reference data rather than prose, so entries are kept close to the original term + short guidance format.

> **Note on completeness:** This is a condensed version of a long glossary — each entry is trimmed to a short usage note rather than the full original explanation (which often includes examples and cross-references). **For full detail on any entry, check the live [source page](#word-list).**

## Symbols
- **+** — OK with numbers in running text (e.g., "300+ attributes"), except in formal contexts.
- **&** — Avoid in headings/body text in place of "and"; OK for UI element names and space-constrained tables.

## A
- **2-Step Verification** — Capitalize for Google's product; lowercase for the generic concept.
- **a / an** — Use "a" before consonant *sounds*, regardless of spelling.
- **A/B testing** — Capitalize, with the slash.
- **abnormal** — Avoid for people; OK for system conditions.
- **abort** — Avoid; use "stop," "exit," "cancel," or "end."
- **about vs. on** — Use "about" in cross-references describing linked content.
- **above** — Avoid for version ranges, document position, or UI direction; OK for non-directional hierarchy.
- **access (verb)** — Avoid where possible; prefer "see," "edit," "find," "use," "view."
- **access token** — Lowercase except at sentence start.
- **account name** — Don't use; say "username."
- **actionable** — Avoid unless clearest option.
- **action bar** — Android: use "app bar" instead.
- **ad tech** — Spell out "advertising technology (ad tech)" on first use.
- **address bar** — Preferred term for the URL bar.
- **ad hoc** — OK in database/analytics contexts; don't hyphenate or italicize.
- **admin** — Spell out "administrator" except in UI labels or Android docs.
- **administrator** — Don't use in Android docs; use "admin."
- **agnostic** — Avoid; use "platform-independent" or similar.
- **AI** — OK without spelling out for most audiences.
- **aka** — Don't use; write "also known as."
- **allowlist (verb)** — Don't use as a verb; OK as a noun.
- **allows you to** — Avoid; use "lets you."
- **alpha** — Lowercase except in product names.
- **America / American** — Use only for the continents/hemisphere; prefer "US"/"United States" for the country.
- **among vs. between** — "Among" for non-distinct items in a group; "between" for distinct items.
- **AM, PM** — All caps, no periods, space before.
- **and/or** — Avoid; use "or" or restructure.
- **Android** — Capitalize for the OS.
- **Android-powered device** — Don't use "Android device."
- **and so on** — Avoid; use "etc." sparingly or restructure.
- **anti-pattern** — Avoid as jargon; be specific.
- **API** — OK for web/language-specific APIs; avoid for individual methods/classes.
- **API Console** (and variants) — Don't use; say "Google APIs Explorer" or "Google Cloud console."
- **API key** — Not "developer key"/"dev key."
- **app** — Preferred for end-user programs; "application" OK for enterprise software or set phrases.
- **app bar** — Formerly "action bar."
- **appendix** — Plural "appendixes."
- **as (causal)** — Avoid; use "because" for clarity.
- **as of this writing** — Avoid; dates the content.
- **authentication / authorization** — "Authenticated" for users, "authorized" for requests.
- **authN / authZ** — Don't abbreviate; spell out.
- **autohealing / autopopulate / autoscaling / autotagging** — One word, no hyphen.
- **autoupdate** — Don't use; say "automatically update."
- **-aware** — Avoid as a compound modifier except in product names.

## B
- **backend** — One word.
- **bare metal** — Lowercase; hyphenate as "bare-metal" when modifying a noun.
- **Base64** — Lowercase except at sentence start; code font only for literal strings.
- **best effort** — Avoid; describe actual behavior.
- **beta** — Lowercase except in product names.
- **big-endian / little-endian** — Hyphenate; lowercase except at sentence start.
- **billing charges** — "Billed charges" = charges on a bill; "billing charges" = cost of billing itself.
- **black-box** — Avoid; use "synthetic monitoring" or "opaque-box testing."
- **Black Friday / Cyber Monday** — Avoid unless literally US-specific; use "peak scale event."
- **blackhat / black hat** — Don't use; use precise terms ("illegal," "unethical," "rule-violating").
- **blacklist** (and forms) — Don't use; use "denylist," "blocklist," "excludelist" (nouns); rephrase verbs.
- **blast radius** — Avoid; use "affected area."
- **blue-green** — Hyphenated, not slash or space.
- **Boolean** — Code font for the keyword; lowercase for the abstract type; capitalize for the mathematics.
- **break-glass** — Avoid; use "emergency access."
- **brown bag** — Avoid; use "learning session"/"lunch and learn."
- **button** — Distinguish from "link."

## C
- **can** — OK for permission, ability, or possible outcomes.
- **canary** — Don't use as a verb; define if used.
- **cell phone / cellular** — Use "mobile phone"/"mobile device"/"mobile data"/"mobile network."
- **checkbox** — One word.
- **CLI** — Don't use generically; name the specific interface.
- **click** — Desktop mouse only; avoid "click on"; hyphenate "right-click," "double-click."
- **click here** — Avoid; write descriptive link text.
- **client secret / client ID** — Lowercase except at sentence start.
- **Cloud console / Cloud SDK** — Don't use; say "Google Cloud console" / "Google Cloud CLI."
- **codebase / codelab** — One word.
- **config** — Avoid outside code; spell out "configuration."
- **confidential** — Data protected from unauthorized access (compare "sensitive").
- **cons** — Avoid; use "disadvantages."
- **console** — Always name which console.
- **copy and paste** — Avoid; say what to enter instead.
- **could** — Avoid; use "can" or "might."
- **curl** — Lowercase, not "cURL."
- **currently** — Avoid; implied and dates the content.

## D
- **dashboard** — Don't use for Google Cloud console; lowercase unless part of a product name.
- **data** — Treat as singular ("data is"), a mass noun ("less data").
- **data center** — Two words.
- **deprecate** — Means "recommend against," not "remove" or "delete."
- **disable** — Avoid for broken items; use "inactive"/"unavailable"/"deactivate."
- **DevOps** — No need to spell out.
- **drop-down** — Omit from "drop-down list/menu" unless needed; don't use alone.

## E
- **each** — Individual items, not a group as a whole.
- **e.g.** — Don't use; say "for example."
- **email** — One word; not used as a verb.
- **enable** — For turning on features; use "lets you" for describing capability.
- **etc.** — Avoid generally.
- **execute** — Prefer "run" unless a more precise term is needed.

## F–G
- **filename / file system** — One word / two words respectively.
- **foo, bar, baz** — Avoid despite developer-community familiarity; use clearer placeholder names.
- **frontend** — One word.
- **functionality** — Prefer "capabilities" or "features."
- **gcloud CLI** — First mention: "Google Cloud CLI."
- **generative AI** — Spell out "generative"; sentence case; don't abbreviate to "gen AI."
- **Google (verb)** — Don't use as a verb.
- **Google Cloud** — Not "GCP," "Cloud Platform," or "Cloud."
- **grandfathered** — Avoid; use "legacy," "exempt."
- **gray-box / gray-hat / graylist** — Avoid; see "black-box"/"blackhat"/"blacklist" guidance.

## H–I
- **hang** — Avoid for unresponsive systems; say "stop responding."
- **healthcare** — One word.
- **high availability (noun) / high-availability (adjective)** — Hyphenate as adjective; "HA" OK after first mention.
- **hotspot** — OK as a noun in database contexts; don't verb it.
- **IAM** — Spell out "Identity and Access Management (IAM)" on first use.
- **i.e.** — Don't use; say "that is."
- **ingest** — Reserve for operations with real processing, not simple copying.
- **in order to** — Avoid; just say "to."
- **internet** — Lowercase.
- **IPsec** — Not "IPSec"/"IPSEC"; no need to spell out.

## J–K
- **jank / janky** — Only for graphics glitches from data loss, not general quality complaints.
- **just** — Usually a fillter word; delete if the meaning survives.
- **key-value pair** — Not "key/value pair."
- **kill** — Avoid; use "stop"/"exit"/"cancel"/"end."

## L–M
- **left-nav / right-nav** — Avoid directional language; use "navigation menu."
- **legacy** — Prefer a more precise term; define if used.
- **leverage** — Avoid when it just means "use."
- **lifecycle** — One word.
- **master / slave** — Avoid entirely; use "primary," "main," "controller," etc.
- **may** — Reserve for policy/legal permission; use "can"/"might" for possibility.
- **mobile** — Don't use as a bare noun; say "mobile phone"/"mobile device."
- **must** — For required actions/states (also "you need to").

## N–O
- **N/A** — Not "NA"; spell out "not available"/"not applicable" on first use.
- **native** — Avoid for people; imprecise as "cloud-native."
- **NoOps** — Avoid; use "fully managed."
- **on-premises** — Hyphenated; not "on-prem," "on premise."
- **OS** — OK abbreviation for "operating system."

## P
- **please** — Don't use in ordinary instructions.
- **plugin (noun) / plug-in (adjective) / plug in (verb)** — Distinguish forms.
- **portal** — Don't use for Google Cloud console.
- **postmortem** — Avoid generally; use "retrospective" (exception: "blameless postmortem" in DevOps/SRE contexts).
- **pre-shared key** — Not "preshared key."

## P (continued)
- **presently, at present** — Avoid because this word or phrase is implied.
- **press** — Use when referring to pressing a key or a key combination to cause an action to occur.
- **presubmit** — Not pre-submit.
- **primitive** — Use with caution. Don't use primitive in a disparaging sense.
- **project** — In Google Cloud documentation, use Google Cloud project on first mention and in any context in which there might be ambiguity about what kind of project you mean.
- **pros** — Don't use. Instead, use a more precise term, such as advantages.

## Q–R
- **quick, quickly** — What might be quick for you might not be quick for others.
- **quota** — In API contexts, often refers to API usage limits.
- **RDP** — Don't use as a verb. Instead, use connect using RDP.
- **re*** — See guidance about hyphens with prefixes.
- **read-only** — Not read only. Always hyphenate read-only.
- **recents screen** — In Android contexts, use instead of overview screen.
- **redline** — Don't use as a verb. Instead, use precise terms appropriate to the context.
- **regex** — Don't use. Instead, use regular expression.
- **rehost** — Use to describe the migration of an app or workload with no changes or minimal changes to that app or workload.
- **repo** — Don't use. Instead, use repository.
- **Representational State Transfer** — Don't use the expanded term; refer to it as REST without explaining what it stands for.
- **reservation, off the** — Don't use.
- **resource record set** — Not resource recordset.
- **retarded** — Don't use. If referring to a system or component being slowed, use the word slowed.
- **retriable, triable** — Don't use retriable or triable, unless a code item uses that spelling.
- **retryable, tryable** — Where possible, write around retryable and tryable.
- **review** — If you mean "read, potentially for the first time," use read instead of review.
- **RFC** — Use a space between RFC and the number (for example, RFC 2318).
- **roll out** — Don't use to mean a sudden or instantaneous launch.
- **RTFM** — Don't use; use a specific pointer phrase instead, such as "for more information, see...".
- **runbook** — Not run book.
- **runtime, run time** — Use the noun runtime for the environment software runs in (e.g., a Ruby or Java runtime).

## S
- **SaaS** — Write out on first mention: software as a service (SaaS).
- **sane** — Don't use. Use a word like valid or sensible.
- **sanity check** — Don't use. Use a term like quick check, confidence check, or preliminary check.
- **SAP** — Pronounced as individual letters, so "an SAP system," not "a SAP system."
- **scale** — Don't use scale alone to say something is large or increasing.
- **screenshot (noun)** — Not screen shot or screensnap. Don't use as a verb; instead say take a screenshot.
- **scroll** — OK as a verb, but prefer an implementation-neutral term if possible.
- **Search (as part of product name)** — Capitalize when referring to a product like Google Search.
- **Search Console** — Capitalize each word.
- **see** — OK generally and for cross-references.
- **select** — Use for choosing among options, selecting text, or marking a checkbox.
- **sensitive** — Sensitive data is data whose release could be harmful.
- **service** — OK to refer to Google products (e.g., GKE, Compute Engine) as services.
- **service level agreement / indicator / objective** — Lowercase except at sentence/heading/list-item start.
- **setup (noun/adjective), set up (verb)** — One word for the noun/adjective, two words for the verb.
- **sexy** — Don't use. Use precise, positive words like fast, powerful, or elegant.
- **SHA-1** — Not SHA1, except in string literals/enums or hyphenated phrases like HSA-SHA1.
- **shall** — Avoid except under legal advice.
- **she, her, hers** — Don't use a gendered pronoun except for a known individual.
- **sherpa** — Use a more precise term, such as guide, if possible.
- **shift left** — Generally avoid for "moving something earlier in time."
- **should, should be** — Generally avoid; ambiguous by definition.
- **sign-in (noun/adjective), sign in (verb)** — Not log in or signin.
- **sign into** — Don't use; use sign in to.
- **sign-on, sign on** — Don't use alone; use the hyphenated form as part of single sign-on.
- **sign-out (noun/adjective), sign out (verb)** — Not log out or signout.
- **simple, simply** — What's simple for you may not be for others; use with care.
- **since** — Use because instead when that's the intended meaning.
- **single most** — Not singlemost.
- **single pane of glass** — Avoid; describes centralized monitoring/control favorably in a way that may not hold up.
- **single sign-on (noun/adjective)** — Hyphenate; abbreviate as SSO after first use.
- **slave** — Don't use; use a domain-appropriate alternative like worker or replica.
- **slice and dice** — Don't use; use specific terms for the task described.
- **smartphone, smart phone** — Don't use; use mobile phone or phone.
- **soon** — Avoid in timeless documentation; can become outdated.
- **spin up** — Avoid unless referring to a hard disk; use a less colloquial term like create.
- **SQL** — "A SQL" (pronounced "sequel"), not "an SQL."
- **ssh and SSH** — Don't use as a verb. SSH is the protocol; ssh is the utility.
- **ssh'ing** — Don't use.
- **startup (noun/adjective), start up (verb)** — One word for the noun/adjective, two words for the verb.
- **static external IP address** — Don't shorten to static IP address or external IP address.
- **status bar** — Not statusbar or status-bar; lowercase except at sentence/heading/list-item start.
- **STONITH, STOMITH** — Avoid graphic or metaphorical framing.
- **style sheet** — Both style sheet and stylesheet are acceptable.
- **sub-command** — Not subcommand.
- **subnet** — OK as a shortening of subnetwork.
- **subtree** — Not sub-tree.
- **subzone** — Not sub-zone or sub zone.
- **such as** — Use to introduce examples or comparisons.
- **surface** — Avoid as a transitive verb; use make people aware of or expose instead.

## T
- **tab** — Use "page," not "tab," for console sub-pages.
- **table name** — Two words; set specific table names in code font.
- **tablet** — OK; use device if unsure whether it's a tablet or phone.
- **tag** — See the guidance for element (in HTML contexts, distinguish tag from element).
- **tap** — In Android docs, for on-screen/soft buttons.
- **tap & hold, tap and hold** — In Android docs, don't use; use touch & hold.
- **tarball** — Don't use; use tar file.
- **target** — Avoid as a verb, especially referring to people.
- **terminate** — Avoid as a synonym for stop; use stop, exit, cancel, or end.
- **text box, textbox** — Don't use; use box.
- **their (singular)** — See they.
- **then** — Include helper words like then in if...then statements even though casual usage often omits it.
- **they (singular)** — Preferred gender-neutral pronoun.
- **third party (noun), third-party (adjective)** — Two words as a noun, hyphenated as an adjective.
- **this, that** — Follow with a noun where possible for clarity.
- **timeframe** — Not time frame; prefer period, schedule, deadline, or when.
- **timeout (noun), time out (verb)** — One word for the noun, two words for the verb.
- **timestamp** — Not time stamp.
- **time to live** — Not time-to-live; abbreviate TTL after first use.
- **time zone (noun), time-zone (adjective)** — Two words as a noun, hyphenated as an adjective.
- **tl;dr** — Don't use; use something like "To summarize," or restructure.
- **toolkit** — Not tool-kit or tool kit.
- **touch** — In Android docs, don't use; use tap.
- **touch & hold** — Not "touch and hold."
- **touchscreen** — Not touch screen.
- **traditional** — Use a more precise term if possible.
- **transpile** — Not transcompile.
- **tribal knowledge, tribal wisdom** — Don't use; use a less figurative term for group-held knowledge.
- **trojan** — Lowercase when referring to malware.
- **turn on** — In procedures, use the label/action tied to the actual UI element.
- **tutorial** — OK to use.
- **type** — Prefer enter, since text can be entered by typing, pasting, or speaking.
- **typically** — Use to describe what's usual under normal circumstances.

## U
- **UI** — Don't use generically for a page or dashboard.
- **unarchive, uncompress, untar, unzip** — Don't use; use extract.
- **uncheck** — Don't use for clearing a checkbox; use clear.
- **under** — Don't use for a range of version numbers.
- **Unicode** — Not UNICODE.
- **Unix-like** — Not Unixlike or Unix like.
- **Unix epoch time** — Preferred over Unix time or epoch time for a count of seconds since the Unix epoch.
- **unselect** — Don't use; use clear (checkboxes) or deselect (other UI elements).
- **unsighted** — Don't use; see blind.
- **US** — OK as an abbreviation for United States.
- **user** — Use only for the user of the software your reader is developing.
- **user base** — Not userbase.
- **using** — Add "by" (by using) when the logic could otherwise be ambiguous.
- **UTF** — Keep the hyphen in encoding names: UTF-8, UTF-16, UTF-32.
- **utilize, utilization** — Use with caution; don't use utilize when you mean use.

## V
- **v (abbreviating version)** — Lowercase.
- **via** — Don't use.
- **vice versa** — Don't use; spell out the relationship.
- **virtual machine (VM) instance** — Use when first introducing VMs on a page.
- **visually challenged** — See blind.
- **VLAN attachment** — Don't use "interconnect attachment (VLAN)" or variants.
- **voila** — Don't use.
- **voodoo** — Don't use; use mysterious, complicated, or nondeterministic.
- **vs.** — Don't abbreviate; spell out versus.

## W
- **wake lock (noun), wake-lock (adjective)** — Two words as a noun, hyphenated as an adjective.
- **walkthrough** — Not walk-through.
- **war room, warroom, war-room** — Don't use; name the activity or team precisely.
- **warm** — Avoid jargon like warm failover, warm standby, warm spare where possible.
- **we** — Don't use first-person plural pronouns to address the reader performing tasks.
- **web (lowercase)** — Lowercase in running text.
- **WebAssembly, Wasm** — Follow the capitalization in the WebAssembly spec.
- **web application firewall (lowercase)** — Lowercase in running text.
- **webmaster, web master** — Don't use; name the specific role (e.g., website owner/administrator).
- **web server** — Not webserver.
- **whether** — Distinguish from if; see general grammar guidance on the distinction.
- **while** — Don't use to indicate contrast; use although.
- **white-box, whitebox** — Avoid for monitoring/testing; be specific.
- **white glove, white-glove, whiteglove** — Avoid; use high-touch, premium, or platinum-level.
- **whitehat, white hat, white-hat** — Don't use; name the kind of compliance (legal, ethical, rule-following).
- **white label, whitelabel, white-label** — Don't use; use unbranded, unlabeled, or blank label.
- **whitelist, whitelisted, whitelisting** — Don't use; see blacklist/denylist guidance.
- **whitepaper** — Not white paper; use a more precise term where possible.
- **whitespace** — Not white space.
- **wildcard** — Not wild card.
- **will** — Avoid (and its past tense, would).
- **wish** — Don't use; use want or need.
- **with** — Avoid using *with* to express ownership or use; rephrase with a more direct verb.
- **workload** — Define your intended meaning on first use — it can mean software, app resources, or physical components.
- **World Wide Web** — Don't use; use web.
- **would** — Avoid; use can where possible.

## Y–Z
- **ymmv** — Don't use; use something like "your results might vary."
- **you** — Use instead of user to address the document's reader.
- **zippy** — Don't use for expander arrows generally; OK only for the specific Zippy widget in Closure.
